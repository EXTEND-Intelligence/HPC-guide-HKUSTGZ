# 实验目录模板

一个参考布局：代码、数据、结果分开放，每次运行一个独立目录。可按自己的项目调整。

```text
my-project/
├── configs/                      实验配置
├── src/                          代码
├── slurm/                        作业脚本
├── logs/                         Slurm 日志与 sacct 记录
├── data/                         数据集，或指向单独数据目录的链接
├── outputs/
│   └── <任务或数据集>/<方法>/seed-23/<run-id>/
│       ├── config.yaml           本次运行的完整配置
│       ├── metadata.json         参数、Git commit、依赖、作业号
│       ├── metrics.csv           原始指标
│       ├── evaluation/           评估明细
│       └── checkpoints/
└── figures/<任务或数据集>/        图与对应的小型汇总数据
```

命名建议：

- `run-id` 包含时间和 Slurm 作业号；数组作业再加上数组编号，例如 `20261014-123456_7`。
- 实验设置有关键差异时（如模型规模、数据划分），把它写进目录名，方便查找；但完整设置仍以 `config.yaml` 为准，目录名不能代替配置。
- 每次重跑用新目录，不覆盖旧结果。

版本管理：

- Git 记录代码、配置和小型分析材料；checkpoint、原始大数据另外存放和备份。
- 一批实验提交后，不要修改它读取的代码和配置。必须修改时，复制出独立的版本目录并记录下来，不要让同一批实验混用两个版本。
- `figures/` 是否放进 Git 由项目决定，但要保留画图用的汇总数据和绘图脚本。

记录依赖和代码版本的命令见 [结果管理](../docs/09-results-and-reproducibility.md)。
