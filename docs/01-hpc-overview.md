# 01 · 认识 HPC：节点、作业与 Slurm

读完这一章，你会知道 HPC 由哪几部分组成、各自用来做什么，以及"申请资源"到底申请的是什么。

## 两种节点

HPC 集群是一组通过高速网络连接起来的服务器，每台服务器叫一个**节点（node）**。你会接触两种节点：

| | 登录节点（login node） | 计算节点（compute node） |
|---|---|---|
| 怎么进入 | 用 SSH 直接登录 | 通过 Slurm 申请，分配后才能使用 |
| 适合做 | 编辑文件、传输数据、使用 Git、提交和查询作业 | 训练、评估、编译、调试 |
| 不要做 | 训练、大规模数据处理、长时间占满 CPU | 使用超出申请量的资源 |
| 谁在用 | 所有用户共用 | 申请到的核和内存只给你的作业使用 |

> **注意：** 登录节点是所有人共用的入口。在上面跑训练会拖慢其他人，也可能被管理员终止。

**怎么判断自己在哪个节点：** 执行 `hostname` 看主机名；在计算节点的作业里，`echo "$SLURM_JOB_ID"` 会输出作业号，在登录节点则为空。

## 作业：一次资源申请

**作业（job）** = 一份资源申请 + 要执行的命令。提交作业时，你要告诉 Slurm：

- 用哪个**分区（partition）**：一类计算节点的集合，比如普通 CPU、A40 GPU、免费调试。分区也常被叫作"队列"。
- 要多少 **CPU 核**、多少**内存**、几块 **GPU**。
- 最长运行多久（**时间上限**）。
- 运行什么命令。

**Slurm** 是集群的作业调度系统：负责排队、把作业分配到合适的计算节点、到时间收回资源。每个作业都有唯一的**作业号（job ID）**。

你申请到的不是"一台属于你的服务器"，而是某台计算节点上的一部分核、内存和时间。作业一旦结束（正常完成、出错、超时或被取消），这些资源就会被收回。

## 一个作业的生命周期

```text
sbatch 提交 → PENDING 排队 → RUNNING 运行 → 结束（COMPLETED / FAILED / TIMEOUT / CANCELLED）
```

| 状态 | `squeue` 中的缩写 | 占用资源、计费吗？ |
|---|---|---|
| 排队（PENDING） | `PD` | 不占用，不计费 |
| 运行（RUNNING） | `R` | **占用并计费**，即使程序在空转 |
| 已结束 | 不再显示 | 资源已自动释放 |

## 二期常用分区

| 分区 | 用途 | 费用 |
|---|---|---|
| `debug` | 短时调试，最长 30 分钟 | 免费 |
| `i64m512u` | 普通 CPU 计算 | 0.02 元/核·小时 |
| `i64m1tga40u` | A40 GPU 计算 | 0.50 元/卡·小时，CPU 另计 |

分区名、上限和价格以平台实时配置为准。查询方法见 [Slurm 作业](04-slurm-basics.md)，计费细节见 [费用与预算](08-pricing-and-budget.md)。

## 学校的几个 HPC 平台

学校有多期 HPC 平台，登录地址和使用方式都不同。**本教程只讲二期。**

| 平台 | 登录地址 | 说明 |
|---|---|---|
| **二期** | `hpc2login.hpc.hkust-gz.edu.cn` | **本教程主线**：CPU + NVIDIA GPU，使用 Slurm |
| 一期 | `hpc1login.hpc.hkust-gz.edu.cn` | 使用 `jsub` / `jjobs`，不能照搬本教程的 Slurm 命令 |
| 三期（ACD） | `hpc3login.hpc.hkust-gz.edu.cn` | 不开放互联网，规则不同，见官方三期手册 |
| 四期（国产） | `hpc4login.hpc.hkust-gz.edu.cn` | 国产硬件平台，环境不能直接照搬 |
| EDA | — | 电子设计自动化专用平台 |

有账号不代表能用所有平台，能用哪些以你的开通情况为准。

> **提示：** 登录后看到的主机名（如 `mgmt-3`、`mgmt-4`）只是管理节点的名字，**不代表**你在三期或四期。判断平台，看你 SSH 连接的是哪个地址。

本教程不需要 Docker，Python 虚拟环境（venv 或 conda）通常就够用。
